Moderation & Safety\n\n#### Report System\n- **Report Types**: User, Product, Review, Message\n- **Modal Interface**: In-app report submission\n- **Submission Locations**: \n  - Inbox (for sellers)\n  - Product page (for listings)\n  - Review section (for reviews)\n- **Implementation**: `ModerationRepository.kt`, `ModerationModels.kt`\n\n#### Ban System\n- **Ban Types**:\n  - Temporary bans (7 days, 30 days, etc.)\n  - Permanent bans\n- **Ban Reasons**: Tracked and displayed\n- **Appeal Status**: Pending, Approved, Rejected\n- **Implementation**: `ModerationRepository.kt`\n\n#### Appeal System\n- **Appeal Screen**:\n  - Clear ban reason display\n  - Time counter for ban duration\n  - Appeal submission form\n  - Appeal status tracking\n- **Appeal Restrictions**:\n  - Maximum 3 appeals per ban\n  - 7-day cooldown between appeals\n  - Can browse while banned\n  - Cannot chat/post/modify profile while banned\n- **Implementation**: `AppealManager.kt`\n\n#### Autoban for Repeated Violations\n- **Trigger**: 2 repeated link/phone violations\n- **Process**:\n  - 1st violation: Warning message\n  - 2nd violation: 7-day ban\n  - Automatic enforcement\n- **Implementation**: `ModerationRepository.kt`\n\n### 6. User clicks \"Message Seller\"\n2. Create/get conversation\n3. Validate message (check for links/phones)\n4. Send message with product attachment\n5. Store offline copy\n6. Send notification to seller\n7. Sync when online\n\n### Report Flow\n1. User submits report\n2. Report stored in Supabase\n3. Admin reviews report\n4. Action taken (warning, ban, etc.)\n5.
